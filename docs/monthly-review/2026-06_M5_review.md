## 3. 学到的关键概念

> 每条都写成「能给同事讲 3 分钟」的版本。

1. **「weight shift = 防前视的物理基础」**：`weights[t]` 的语义必须是「`t` 时刻末已知，
   赚 `t→t+1` 的收益」。引擎内部 `weights.shift(1)` 是这个约定的唯一实现入口；离开
   引擎自己拼乘法 99% 会写错（演示见陷阱 1：Sharpe 从 -0.4 → 66.5）。
2. **「成本必须显式」**：`VectorEngine(cost_bps=None, cost_model=None)` 在构造函数里
   抛错。「忘了加成本」是回测里最常见的诚实问题，编译器是最好的纪律官。
   接入 `costs.AShareCostModel` 后，`reversal_5d` 的扣费年化从 -5% 滑到 -23%——
   印花税 + 142 的年化换手，10bps 单边都不够算的。
3. **「同一份权重 DataFrame 在两个引擎里能是两个策略」**：parity check 时把月度调仓
   用 `ffill` 铺成日度常量 1/N，自研引擎读成「无 Δw、无成本」，vectorbt 读成「每天
   拉回 1/N、天天付费」，10bps 下终值差 -0.14% 不是 bug，是语义错位。这条已经写进
   `reports/m05_vectorbt_parity.md` 第 5 节和 `pitfalls.md`。
4. **「IS Sharpe 是文学创作，DSR 是把作者请回现实」**：在零 Alpha 的合成数据上扫 10
   个动量窗口 × 8 个 split = 80 trials，每个 split 选出的「最佳窗口」都不同，
   聚合 OOS Sharpe ≈ 0，DSR ≈ 0。N 越大、Sharpe 估计量方差越大、DSR 折扣越狠 ——
   这是「为什么要在论文里报告 N」的代码级答案。

## 4. 踩过的坑

- **浮点精度污染 Sharpe**（已修）：constant return series 的 `std()` 不是真正的 0，
  按 `> 0` 判断会算出 7e16 的 Sharpe。修复：相对均值的 `vol_floor = 1e-12 * max(|mean|, 1e-6)`。
  已写测试 `test_constant_positive_return_zero_volatility` 守住。详见 pitfalls 2026-05-20 条。
- **ffill 月度调仓权重 = 两个引擎读两个策略**（已识别+留档）：见上文「关键概念 3」
  和 `pitfalls.md` 2026-05-24 条。
- **Walk-Forward 一开始想把 train slice 喂给 strategy_fn**（已修）：那样会切掉策略的
  lookback（比如 20 日均线在窗口前 20 天全是 NaN），相当于沉默地把每个窗口前段算
  成「无信号」。最后改成 strategy_fn 拿到 *full panel* 一次性算完权重，
  walk_forward driver 只切权重不切计算。代价是：strategy_fn 必须自己保证无前视，
  driver 不替你管。这个约束写在 `validation.py` 的模块文档里。
- **`cost_bps` 公式与 vbt 的细微差**：自研引擎是 `Σ|Δw| × bps/10000`（固定 NAV），
  vbt 是 NAV 浮动版。常规策略差 < 1 bp 年化；年化换手 > 50 的极端策略最多差 ~10 bp。
  parity 报告第 7 节已经写进档，不修。
